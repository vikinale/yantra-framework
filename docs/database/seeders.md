# Database Seeders

Seeders populate your database with default or test data. A seeder is a class with a `run(Database $db)` method — typically implementing `System\Contracts\SeederInterface` — that the `db:seed` command instantiates and executes against the application connection.

```bash
php yantra make:seeder UsersTableSeeder
php yantra db:seed
```

## Creating seeders

```bash
php yantra make:seeder UsersTableSeeder
```

This scaffolds `database/seeders/UsersTableSeeder.php` in the `Database\Seeders` namespace.

## Writing seeders

Implement `SeederInterface` and use the injected `Database` connection:

```php
<?php
declare(strict_types=1);

namespace Database\Seeders;

use System\Contracts\SeederInterface;
use System\Database\Database;

final class UsersTableSeeder implements SeederInterface
{
    public function run(Database $db): void
    {
        $stmt = $db->prepare(
            'INSERT INTO users (name, email, password, role) VALUES (?, ?, ?, ?)'
        );

        $stmt->execute(['Admin', 'admin@example.com', password_hash('admin', PASSWORD_DEFAULT), 'admin']);
        $stmt->execute(['User',  'user@example.com',  password_hash('user',  PASSWORD_DEFAULT), 'user']);
    }
}
```

You are free to use models or the [query builder](/database/query-builder) inside `run()` instead of prepared statements:

```php
public function run(Database $db): void
{
    \App\Models\User::create([
        'name'  => 'Admin',
        'email' => 'admin@example.com',
    ]);
}
```

## Composing seeders

There is **no `call()` method**. A root seeder delegates by instantiating other seeders and invoking their `run()` directly:

```php
<?php
declare(strict_types=1);

namespace Database\Seeders;

use System\Contracts\SeederInterface;
use System\Database\Database;

final class DatabaseSeeder implements SeederInterface
{
    public function run(Database $db): void
    {
        (new UsersTableSeeder())->run($db);
        (new PostsTableSeeder())->run($db);
        (new CategoriesTableSeeder())->run($db);
    }
}
```

## Running seeders

```bash
# Run the default seeder (Database\Seeders\DatabaseSeeder)
php yantra db:seed

# Run a specific seeder class
php yantra db:seed --class=Database\\Seeders\\UsersTableSeeder
```

The default class can be changed with the `database_seeder` key in `App/Config/db.php`. Note that [`migrate:refresh`](/database/migrations) also runs the default seeder after re-migrating, unless you pass `--no-seed`.

::: warning Gotchas
- The runner resolves the seeder by fully-qualified class name and requires a `run()` method — make sure your seeder is autoloadable under the `Database\Seeders` namespace.
- The stub generated by `make:seeder` currently type-hints `PDO`; the runner passes a `System\Database\Database` instance (per `SeederInterface`), so update the type hint to `Database` as shown above.
- Seeders are not wrapped in a transaction for you. Wrap `run()` in `Database::beginTransaction()` / `commit()` if you need all-or-nothing seeding.
- Seeding is not idempotent by default — use `ignore()->insert(...)` or upserts from the [query builder](/database/query-builder) if a seeder may run more than once.
:::
